# Inspire Demo Q&A / Inspire Demo 双语问答

## 1. Is this Inspire demo controlled by reinforcement learning? / 当前 Inspire demo 是由强化学习控制的吗？

**English:** Not yet. It is a deterministic scripted joint-position baseline. It validates the five-finger model, pointing motion, fingertip measurement, task phases, and success criteria. RL training is a later milestone.

**中文：** 还不是。当前是确定性的 scripted joint-position baseline，用于验证五指模型、指向动作、指尖测量、任务阶段和成功判定。RL 训练是后续阶段。

## 2. Why do you need a scripted baseline first? / 为什么要先做 scripted baseline？

**English:** It separates environment and control bugs from learning problems. It also provides a reproducible reference that a learned policy must match or outperform.

**中文：** 它可以把环境或控制错误与学习问题分开，也为 learned policy 提供一个可复现、可比较的基线。

## 3. What does Inspire add to the original demo? / Inspire 版本相比原 demo 增加了什么？

**English:** The left hand is an articulated five-finger model. Finger joints create the pointing gesture, and the measured endpoint is a site on the modeled index fingertip rather than a rigid hand coordinate.

**中文：** 左手变成了可动五指模型。指向姿态由手指关节产生，测量端点是模型真实食指尖上的 site，而不是刚性手部坐标。

## 4. How many joints are in the model? / 模型一共有多少个关节？

**English:** MuJoCo exposes 53 modeled joints: 29 body joints and 24 hand joints. The current task actively commands seven left-arm joints and twelve left-hand joints.

**中文：** MuJoCo 中共有 53 个模型关节：29 个身体关节和 24 个手部关节。当前任务主动控制 7 个左臂关节和 12 个左手关节。

## 5. Why does the right hand look different? / 为什么右手外观和左手不同？

**English:** The right hand is inactive in this task. We display the original G1 human-shaped rubber-hand visual there for a natural neutral pose, while retaining the hidden right Inspire joints internally for model dimensional consistency. The animated left hand remains fully articulated.

**中文：** 右手在本任务中不参与动作。为了让静止姿势更自然，显示的是原始 G1 人形 rubber-hand visual；内部仍保留右侧 Inspire 关节以保持模型维度一致。参与动画的左手仍是完整可动的 Inspire 手。

## 6. Is the robot really pointing with its finger joints? / 机器人真的是通过手指关节做指向动作吗？

**English:** Yes. The index joints stay almost straight while the thumb, middle, ring, and little fingers curl. The pose is generated by the twelve actuated left-hand joint targets.

**中文：** 是的。食指关节接近伸直，拇指、中指、无名指和小指弯曲。该姿态由 12 个左手关节 target 产生。

## 7. What is the task endpoint? / 任务的 endpoint 是什么？

**English:** It is the `left_index_tip` site attached to the modeled left index finger. Fingertip-to-target Euclidean distance is used for success evaluation.

**中文：** Endpoint 是连接在左手食指模型上的 `left_index_tip` site。成功判定使用指尖与目标中心之间的欧氏距离。

## 8. What does `target-radius` mean? / `target-radius` 是什么意思？

**English:** It is the numerical success radius. The fingertip counts as touching when its distance to the target centre is no greater than this value. The default is 0.045 m, or 4.5 cm.

**中文：** 它是数值判定使用的成功半径。当指尖到目标中心的距离不超过该值时算作触碰。默认值为 0.045 m，也就是 4.5 cm。

## 9. What does `target-visual-radius` mean? / `target-visual-radius` 是什么意思？

**English:** It changes only the size of the solid target sphere shown in the viewer. It does not change the numerical success radius. The default is 0.018 m.

**中文：** 它只改变 viewer 中实心目标球的显示大小，不改变数值成功半径。默认值为 0.018 m。

## 10. What does `required-hold` mean? / `required-hold` 是什么意思？

**English:** It is the minimum accumulated time the fingertip must remain inside the success region during TOUCH/HOLD. The default is 1.5 seconds.

**中文：** 它是在 TOUCH/HOLD 阶段，指尖必须位于成功区域内的最小累计时间。默认值为 1.5 秒。

## 11. What result did the verified run achieve? / 验证运行取得了什么结果？

**English:** The minimum displayed distance was 0.0000 m, accumulated valid touch time was 2.002 s, and the run returned `success=True`. This is a fixed-target scripted result.

**中文：** 显示精度下的最小距离为 0.0000 m，有效累计触碰时间为 2.002 s，并返回 `success=True`。这是固定目标上的 scripted 结果。

## 12. Why does the distance rise again at the end? / 为什么曲线最后距离又上升？

**English:** That is the RETURN phase. After satisfying the hold requirement, the hand intentionally leaves the target and returns toward its neutral pose.

**中文：** 这是 RETURN 阶段。满足保持要求后，手会主动离开目标并返回 neutral pose。

## 13. Can the arm adapt if the target moves? / 如果目标位置变化，手臂可以自适应吗？

**English:** Not in the current baseline. The target is calculated from the fixed `TOUCH_ARM` pose, so moving the target does not recompute the arm configuration. We need inverse kinematics or a target-conditioned learned policy for adaptation.

**中文：** 当前 baseline 不能。目标是根据固定的 `TOUCH_ARM` 姿态计算的，移动目标不会重新计算手臂姿态。要实现自适应，需要 IK 或根据目标状态输出动作的 learned policy。

## 14. Why add IK before RL? / 为什么在 RL 之前增加 IK？

**English:** IK quickly verifies reachability and provides an adaptive reference controller. It reduces the risk of training against impossible targets and gives the learned policy a stronger comparison baseline.

**中文：** IK 可以快速验证目标是否可达，并提供一个自适应参考控制器。它能减少对不可达目标进行训练的风险，也为 learned policy 提供更强的比较基线。

## 15. What is RL? / RL 是什么的简写？

**English:** RL stands for reinforcement learning. An agent selects actions, receives rewards, and improves a policy to maximize expected cumulative reward.

**中文：** RL 是 Reinforcement Learning，即强化学习。Agent 选择动作、获得 reward，并改进 policy，以最大化期望累计回报。

## 16. What is an RL objective? / 什么是 RL objective？

**English:** It is the quantity the agent is trained to maximize, usually expected discounted cumulative reward. In this task, the reward should encourage smaller fingertip distance, valid sustained touch, task completion, and smooth motion.

**中文：** 它是 agent 训练时要最大化的目标，通常是期望折扣累计回报。本任务会鼓励更小的指尖距离、持续有效触碰、任务完成和动作平滑。

## 17. What is the planned reward? / 计划中的 reward 是什么？

**English:** A first version is distance penalty plus touch and completion bonuses, minus a smoothness or unnecessary-motion penalty. The exact weights must be tuned experimentally.

**中文：** 第一版可以由距离惩罚、触碰与完成奖励，以及平滑性或多余动作惩罚组成。具体权重需要通过实验调节。

## 18. Why DQN or PPO? / 为什么考虑 DQN 或 PPO？

**English:** DQN reuses our validated A3 infrastructure and supports a compact discrete action design. PPO is a useful comparison if continuous multi-joint actions are more natural or DQN motion becomes jerky.

**中文：** DQN 可以复用已经验证的 A3 基础设施，并适合规模较小的离散动作。若多关节连续动作更自然，或 DQN 动作明显抖动，可用 PPO 作为比较。

## 19. Do you need to train a model for the dry run? / Dry run 现在需要训练 model 吗？

**English:** No. The dry-run goal is to validate the environment and task definition. Training is required for the final learned-policy claim, but it should begin after target adaptation, observations, actions, reward, and termination rules are stable.

**中文：** 不需要。Dry run 的目标是验证环境和任务定义。最终要声称 learned policy 时必须训练，但应在目标自适应、observation、action、reward 和 termination 都稳定后再开始。

## 20. Why are detailed finger contacts disabled? / 为什么禁用了详细手指碰撞？

**English:** Imported detailed hand collision meshes can interfere with the scripted pointing pose. This baseline therefore evaluates a virtual touch using fingertip distance. Physical contact can be introduced later with simplified collision geometry and retuned control.

**中文：** 导入的详细手部碰撞网格可能干扰 scripted 指向姿态，因此当前通过指尖距离判定虚拟触碰。后续可使用简化碰撞体并重新调整控制参数，再加入物理接触。

```bash
source .venv/bin/activate
mjpython final_project/inspire/reach_touch_inspire_demo.py
```

```bash
python final_project/inspire/reach_touch_inspire_demo.py \
  --no-viewer \
  --csv final_project/inspire/reach_touch_inspire_metrics.csv
```
